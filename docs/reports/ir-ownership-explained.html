1. The problem

A neograph pipeline stores every node's output in one shared bag. When a node needs a value, something has to answer: which value in the bag is meant?

Today, several parts of the framework answer that question independently, each by scanning the bag and comparing types. They do not all agree. When they disagree, nothing raises — a wrong value is returned and the run completes.

The shape of every instance

for value in state:              # walk the bag
    if isinstance(value, Claim): # match by type
        return value             # take the first (or last) hit

There is no record of which producer was meant. The answer is recomputed from scratch, at each site that needs it, from a bag whose contents depend on declarations those sites know nothing about.

Two consequences have shipped to a user, both silently:

Consequence 1 — a boundary returned the wrong object

A sub-construct declared output=Case. It also declared context=["opening"], which puts a second Case into the same bag. The scan matched the injected one.

the node computed  : Case(docket='D-1', readings=5, claims=3)
the boundary returned: Case(docket='D-1', readings=5, claims=0)   # the opening case

context=None        -> boundary = SETTLED
context=['opening'] -> boundary = OPENING       no error, exit 0

Adding an input declaration silently re-pointed an unrelated output. The user found it by dumping compiled state and comparing it against what the branch demonstrably computed.

Consequence 2 — the exported artifact computes a different answer than the pipeline

The runtime scanned forward and took the first match. The Agent Spec exporter scanned in reverse and took the last. Same construct:

runtime : sink consumes a     (forward scan, first match)
export  : wires  b -> sink    (reverse scan, last match)

Export a working pipeline, run it elsewhere, get a different answer. Neither surface complains.

2. How you observe it

This class of defect has no failure signal. It has these symptoms instead.

SymptomWhat you actually see
Green runs, wrong dataThe pipeline completes, every gate passes, and a downstream step reasons over a value nobody selected.
Action at a distanceAdding an unrelated declaration changes an existing binding. Nothing in the changed line mentions the thing that broke.
Types invented for distinctnessA user adds a wrapper type whose only job is to be unique in a bag. One shipped with the docstring “distinctness is the whole of its job”, against that codebase's own rule about types that only move shapes.
The same fix, repeatedlyFive times in five months, someone discovered this fresh and fixed it the same way.
Comments citing authorities that do not existThree verified. One asserted it mirrored “the assembly-time validator's single-type resolution” — the validator performs no resolution.

The recurrence, measured

Each of these is the same fix — resolve the answer once at assembly, store it as a field on the IR, have consumers read the field. Found and applied independently, five times:

fan_out_param        2026-04-06
handoff_param        2026-07-13
handoff_channel      2026-07-14
output_from          2026-08-25
input_source_field   2026-08-27

git log --reverse -S<field> -- src/neograph/node.py src/neograph/construct.py

The last two are two days and one day old. The convergence is the tell: when unrelated people independently invent the same fix, the fix is a missing rule, not a series of coincidences.

3. Why it keeps coming back

The correct pattern is already written down in AGENTS.md. It is written as a precedent — “the pattern to copy for any future new IR capability” — not as an invariant. A precedent is something you may follow. Nothing stops you doing otherwise.

And there is a reason to do otherwise: the shortcut is always available. As long as code can enumerate the bag, re-deriving the answer locally is easier than finding the field someone stamped.

4. How other systems solve this

This is not a novel problem. Any system where steps produce values into a shared space, and later steps consume them, meets it. The solutions converge, and they converge on the same answer.

SystemSame problemHow it is solved
Compilers
any language with scopes		 Which declaration does this identifier refer to? A dedicated name-resolution pass builds a symbol table. Later passes read the resolved binding. Type checking, optimisation and codegen never re-resolve a name; if they did, they could disagree.
SSA form
LLVM and most modern IRs		 Which assignment does this use read? Each value gets exactly one definition, and every use points at that definition directly. The question stops existing. Where control flow makes it genuinely ambiguous, a phi node names the alternatives explicitly rather than leaving it implicit.
Build systems
Bazel, Buck		 Which output satisfies this input? Dependencies are declared, not discovered. A build rule cannot glob the output directory looking for something that fits. That restriction is what makes the build reproducible and remotely cacheable.
Terraform Which resource does this attribute come from? An explicit reference (aws_instance.web.id) creates a graph edge. There is no “find a resource of this type”. Ambiguity is a plan-time error, not a runtime surprise.
Airflow XCom
the closest analogue		 Tasks push values into a shared store; downstream tasks pull them. Instructive as a negative example. Classic XCom pull-by-key is exactly a bag lookup, and it produced the same class of bug. The fix, in the TaskFlow API, was to make outputs into explicit, referenced objects (XComArg) so the dependency is declared, not searched for.
DI containers
Spring, Guice, Dagger		 Which bean satisfies this dependency? Resolution happens once at wiring time. Two candidates of the same type is an error at startup (NoUniqueBeanDefinitionException) that you fix by naming one (@Qualifier). Notably: they refuse rather than guess, and Dagger moves the whole resolution to compile time.
LangGraph
the substrate neograph compiles to		 A dict of state channels shared by every node. It does not solve it — it is the bag. That is fine for LangGraph, whose contract is “you manage state”. neograph's entire value proposition is being stricter than that, which is exactly why the responsibility lands here.

The pattern the field has settled on

Resolve references in one dedicated pass, reify the answer as data attached to the program, and have every later consumer read that data rather than recompute it. Where the reference is genuinely ambiguous, either refuse (DI containers) or name the alternatives explicitly (SSA's phi). What nobody does is let five consumers each search a shared namespace with their own precedence rule.

The proposal below is that pattern, named in the vocabulary the codebase already uses.

5. What we propose

5.1 One owner

_ir_normalize.py, which already runs inside Construct.__init__, becomes the only place that answers “which value is meant”. It is the right owner for a concrete reason: assembly is the only moment when declaration order, the modifier-adjusted producer set, and the enclosing boundary all exist at once. The runtime has the values but has lost the intent; the exporters have the declarations but have repeatedly diverged from the runtime.

5.2 The answer becomes data

A small closed set of types, each naming one kind of place a value can come from:

PeerField(field)        # a named upstream producer's state field
Port()                  # the enclosing construct's input port
EachItem()              # the fanned-out item
LoopCarry()             # this node's own append-list, latest element
HandoffChannel(channel) # a Portal mesh channel
LastPresent(fields)     # ordered candidates; take the last one PRESENT

These are stored in a table the normalizer writes and nobody else can: Node.sources, Construct.boundary_source, Construct.input_source.

Why LastPresent is not the scan wearing a disguise

It is the honest encoding of one legitimate case: a branch boundary satisfied by a different node per arm. The candidate set and its order are decided at assembly — type filtering happens there, once. All that remains at runtime is which arm actually ran, which reduces to whether a field is present.

No isinstance at runtime. Presence cannot pick the wrong one of two values; type-matching can. This is the same move SSA makes with phi: make the alternatives explicit instead of leaving them to a search.

5.3 One rule for every consumer, with no exemptions

A module that needs to know which value is meant does exactly one of: read a Source and interpret it via read_source(bus, source); serialize Source values from iter_resolved_edges(construct); or render a Resolution the resolver returned. No module outside the normalizer applies a type-compatibility test to choose among candidates.

Checking is still allowed everywhere — verifying that a named pair is type-compatible is not choosing. The banned operation is selection.

The part that answers a specific objection

An earlier draft argued that _suggest_hint — which scans producers only to compose an error message — was a lesser case, because it cannot return a wrong answer. That reasoning was rejected, correctly: being diagnostic-only is not a licence to re-derive.

So the resolver returns Resolved(source) or Unresolved(candidates), where each candidate carries a near-miss reason the resolver computed. The error builder renders that object. The diagnostic consumer and the authoritative consumer now follow the same pattern — “diagnostic-only” stops being a category, because there is nothing left it would exempt you from.

5.4 Two capability removals, so the wrong way stops being writeable

  1. StateBus loses keys(). The bag becomes non-enumerable through the interface. A scan is no longer a bad pattern — it is code that does not compile against the bus.
  2. Source values can only be constructed in _ir_normalize.py, enforced by extending a construction ban the project already runs for five string fields. A consumer cannot fabricate a resolution; it can only read one.

5.5 A rule for when ambiguity is legitimate

The design separates two things that were being confused, which is why an earlier attempt to “just refuse ambiguity” failed with 33 test failures:

KindExampleMechanism
Authored
the author could have named it		Two same-typed inputs; two conflicting markers on one fieldRefuse at assembly. Already the house posture in three places.
Emergent
a runtime fact nobody can name in advance		Which mesh member ran last; which branch arm executedFunnel: the mechanism that creates the fact writes it to one named channel, and consumers read that channel.
Everything elseOne right answer, derivable at assemblyResolve once, store a Source.

The earlier refusal experiment failed because it treated emergent ambiguity as authored — demanding a name the author cannot possibly know. With this taxonomy, the next “should this refuse?” question gets classified instead of re-argued.

6. Why this is the right shape

PrincipleHow it applies here
Information ExpertThe logic goes where the information is. Only assembly has declaration order, the producer set, and the boundary at the same time. The runtime and the exporters each hold half the facts, which is precisely why their answers diverged.
High CohesionThe rules interlock — port-versus-peer precedence, producer ordering, framework-key exclusion. Interlocking rules split across five modules is the five-fix history restated.
Low CouplingConsumers depend on a small typed contract, not on the bag's shape or on each other's precedence conventions. A new resolution rule changes one module.
Parse, don't validateThe unresolved question is parsed once into a type that can only represent resolved answers. Downstream code cannot express the unresolved state, so it cannot mishandle it.
The project's own north star“A LangGraph in which a class of broken programs cannot be written.” This applies that inward: a class of broken framework code stops being writeable.

The property that pays for the whole change

When a resolution rule lands in the normalizer, the edge stream changes — and both exporters change behaviour with no edit. There is no exporter-side rule left to forget to update. That is the direct fix for a defect currently open in the tree, where a boundary feature shipped two days ago and neither exporter learned it.

7. Alternatives, and why they lose

AlternativeWhy not
Refuse all ambiguitymeasured Tried: 33 test failures. Worse than the number — it makes a correct program unwritable. A consumer placed after a Portal mesh has no name it could give, because which member ran last is a runtime fact.
A lint or AST guardDetects the symptom after someone writes it. The project already has such a guard; it makes the right path mandatory while leaving the wrong path available. That is how five instances happened.
Capability-token state keys
keys mintable only by one module		Stops forging a key. Does not stop choosing among keys you legitimately hold — which is the actual defect.
A separate lowered IRBuys a property that normalising inside Construct.__init__ already provides, at the cost of doubling the object model.
Thread resolutions through call signaturesEvery consumer needs a new parameter, and any missed call site silently falls back to old behaviour — the failure mode being removed.
Fix the six open tickets individually and stopThis is the measured status quo. It produced five convergent fixes, four false authority citations, and a sixth instance found last week.

8. What changes for someone using neograph

Most of this is invisible. The parts that are not are improvements, plus one breaking change that only affects code reaching into internals.

8.1 Behaviour a user notices

ChangeEffect
fix Boundaries stop returning the wrong objectAdding context= can no longer re-point an unrelated output=. Pipelines that were silently wrong become right.
fix Export matches runtimeAn exported artifact wires the edges the pipeline actually takes.
fix Wrapper types stop being necessaryNo more inventing a type so it is unique in a bag.
better errors Near-miss diagnostics“No producer” errors carry resolver-computed reasons for each rejected candidate, instead of a separately-derived guess.
new failures Some ambiguity now refuses at assemblyWhere an author could have named the value and did not, assembly fails with a message naming the fix. A pipeline relying on an accidental type-scan win will now fail loudly. That is intended: it was returning an arbitrary value.

8.2 Public API

No change to @node, Construct, compile, run, or any decorator. output_from= (shipped two days ago) keeps its spelling and finally works in export and dump_spec.

8.3 The breaking change

StateBus.keys() is removed, and four IR fields — fan_out_param, handoff_param, handoff_channel, input_source_field — are absorbed into the sources table.

These are internal. They affect you only if you read neograph's IR directly or subclass its state plumbing. On a 0.x project with one downstream consumer this is the sanctioned kind of break; the alternative — keeping both representations — is the same disease in miniature, since two representations of one fact is exactly what is being removed.

9. What it means for the Agent Spec initiative

Agent Spec export was the second surface where the divergence showed up, so this decision changes that work substantially — mostly by removing work.

Agent Spec itemBeforeAfter
Emit an edge for an Each fan-out sourceExporter-side derivation, its own ruleA slot kind in one shared edge stream
Emit an edge for a branch decisionSame, separatelySame stream
Emit port and context= edgesMissing entirely — an open defectSame stream
Honour output_from=Ignored by both exporters — an open P1Read from boundary_source
Adding a resolution ruleEdit each exporter, remember bothNo exporter edit; behaviour follows

Import needs work this decision did not originally cover

Validation found the inbound direction is lossier than anyone had written down. When a foreign Flow is imported, the code reads only the source node's name and discards source_output and destination_input entirely; it also silently drops any edge whose source is not already a reconstructed top-level item. Two foreign edges into one input quietly become a neograph fan-in.

This matters more than it sounds, because import is on a hot path: Portal dispatch imports a runtime-emitted flow on every call. Amendment A4 gives import its own section and a harness leg. Verified at _agent_spec_node_import.py:75-83.

The best news from validation

The roadmap feature most likely to invalidate the design — provides/requires named-contract data flow, whose explicit goal is to decouple a consumer from a producer's name — turns out to be absorbed rather than threatened. The sources table is the single-writer indirection layer that feature's own ticket says it needs. Contract aliasing becomes a normalizer rule; PeerField's meaning does not change. It must land after the foundational steps, or it mints a fifth legacy field.

10. The five amendments

An independent validation pass against the known roadmap returned adopt with amendments. The core survives every roadmap item examined. Three of its claims were narrower than written.

AmendmentWhy it matters
A1The edge stream must cover all data edges, not only the resolution tablesthe big one Each.over, branch-decision reads and context= references live in named declarations outside those tables. As originally specced, each would land as a second exporter-side enumeration next to the fold — the same disease with a named field instead of a positional rule. One open defect is already that bug.
A2Write down the growth rule for the closed setVariants must track kinds of state channel, never features. Otherwise it becomes a tagged union gaining a case per feature. The roadmap implies exactly one new variant in two quarters.
A3Admission criteria for LastPresentIt is the variant every hard case will reach for. Without criteria it becomes last-write-wins under a blessed name — the exact semantics the project has already identified as the disease.
A4Import gets its own sectionSee above. Import is a foreign-bag ingestion site and is on the dispatch hot path.
A5Classify output-field population explicitlyCarried, Selected and the proposed projection features populate output fields. They are a different question and get no Source variant — stating that prevents someone filing them under this decision later.

11. Migration, risk, and the decision you owe

11.1 The steps

Nine steps, each independently landable and gate-verified. The first two stand alone and are worth doing even if the rest is deferred.

StepWhat it does
0Add the types and the construction ban. Build the differential-export harness: two constructs differing only in X must not export identically.
1Fix the open P1 where both exporters ignore output_from=. Delete the false authority comments.
2Stamp the sub-construct port, delete the last input scan, then remove StateBus.keys().
3–6Loop self-feedback; diagnostics as renderers; boundary naming; the foreign-bag marker rule.
7Collapse the four legacy fields into the table.
8Close the “should ambiguity refuse?” question with the taxonomy as the recorded answer.

11.2 What is not covered, stated plainly

The runtime side becomes literally impossible to get wrong. The export side is containment, not impossibility — a construct's node list has to stay walkable, so nothing stops a future exporter from deriving its own edges. The substitute is the differential harness, which turns “the exporter did not learn the new field” from something a reviewer must remember into a test that fails. That is a weaker guarantee, and the design says so rather than glossing it.

11.3 The main risk

The accumulator channel feature — many nodes appending to one channel, read downstream as a union — is the one roadmap item that breaks a premise rather than adding a case. One-producer-per-field is currently load-bearing in three places. The closed set survives with one new variant; the producer model does not survive unchanged. This is known now rather than discovered mid-implementation.

11.4 How we will know it worked

Success, by February 2027: a sweep finds type-match selection only in the normalizer; the bag is still non-enumerable; and the next “which value” feature ships touching only the normalizer and its types, while exporter behaviour changes anyway — proven by the harness, not by review.

Failure: a sixth convergent fix appears outside the normalizer, or a closed-set allowlist grows, or a feature needs per-consumer edits. Any of those means answers are still being delivered as storage rather than as a contract.

11.5 The one question for you

Should the edge stream be total from step 0, or cover only the resolution tables with named edges deferred?

Recommendation: total from step 0. Deferring turns three open tickets into three exporter edits — which is precisely the class this decision exists to abolish. Making it total converts them into slot kinds in one fold, graded by the harness from day one. The marginal cost now is much smaller than the rework later.

Everything else in the plan can be re-sequenced without rework. This one cannot.

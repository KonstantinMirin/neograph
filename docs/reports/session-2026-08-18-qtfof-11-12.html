3. Bug one — qtfof.11: the fan-out result never left the MapNode

Root cause

_lower_each built the Each sub-Flow's terminal boundary as a bare EndNode(name=...) — no declared outputs, no DataFlowEdge feeding it. pyagentspec infers up that chain, so a single empty node erased the whole result:

EndNode.outputs = []                      (built bare)
  -> Flow._get_inferred_outputs()  = []   (reads its EndNodes)
    -> MapNode._get_inferred_outputs() = []   (reads subflow.outputs)
      -> nothing downstream can source a DataFlowEdge from the MapNode
        -> the outermost EndNode falls into qtfof.9's unwirable fallback
          -> a third-party invoke() returns {}

Observed directly before any change: the body executed once per element, and invoke() returned {'outputs': {}}. The graph computed the right thing and threw it away at the boundary.

The design question the ticket demanded be settled first

The ticket refused to be fixed blind: does a MapNode wrap the inferred output in a list, or is the inner shape surfaced as-is? Answered by reading the installed SDK rather than guessing — MapNode._get_inferred_outputs retitles every sub-flow output collected_{title}, and _get_default_reducers assigns APPEND to each, which wraps it in an array. So the inner EndNode declares the terminal producer's bare Properties; the prefix and the list-wrapping are pyagentspec's own doing.

That answer drove the implementation choice: read the lowered node's materialised .outputs, never re-derive the convention. ComponentWithIO.model_post_init materialises inferred Properties at construction, so the MapNode can simply be asked. There is now zero collected_ string literal in src/, and a guard keeps it that way.

The discovery that changed the fix: the auto-wiring flip

This was raised as a HIGH risk in the architect-review atom, before any code was written, and it is the finding that justified the whole review step.

pyagentspec's loader synthesises same-title data edges for a Flow only while data_flow_connections is None — all-or-nothing (_langgraphconverter.py). The plain Each sub-Flow shipped None and depended on that synthesis for its StartNode('item') → body('item') input path.

Adding the EndNode edge — the ticket's actual fix — would have been the sub-Flow's first explicit edge, silently switching synthesis off and starving the body's input. The fix would have converted a missing-result bug into a missing-input bug, and every assertion in the original reproduction test would still have passed, because a constant body returns the same value regardless of what it was handed.

Two consequences, both folded into the same change:

  • The StartNode → body edges are emitted alongside the EndNode edge, generically for both the plain and the fused Each × Oracle branches. That is not a blanket replay of the loader's rule — replayed verbatim on the fused body it would put both variants and the merge onto the EndNode's single input (many sources, one destination, last writer wins). Only the two safe directions are emitted.
  • The reproduction test was strengthened before implementation: the Each body now echoes the element it received, so the collected list must contain three distinct values. A constant result would have certified the broken input path.

The generic wiring also closed a pre-existing gap nobody had filed: the fused Each × Oracle sub-flow already shipped explicit edges, so its item input had never been fed. Those three cells became loadable for the first time.

4. Bug two — qtfof.12: the half that could be proven, and the half that could not

The ticket contained two separable defects. They were graded differently, on purpose.

Half A — the misattribution landed

An ungated Portal peer mesh exports a Swarm, and the conformance walker early-returns portal_mesh_unverified for it — an honest "zero GREEN cells of this shape, so absence of a failure signal is not evidence". A gated mesh exports a Flow (the mesh-exit pause composite), fell past that early return into the outermost-EndNode check, and was reported as outermost_end_node_unwired — that is, filed against neograph-qtfof.9, a ticket that has landed and whose fix provably cannot reach this shape.

Filing an open gap against a closed bead makes the conformance report claim the gap is already fixed. The gated mesh now gets the same portal_mesh_unverified predicate its ungated sibling does, detected structurally off the artifact (an AgentNode whose .agent is a Swarm — the only such construction site). Both predicates sit at the same tier, so the verdict does not move: the finding is re-addressed, not promoted. That is asserted explicitly, so a future change cannot quietly turn a re-attribution into a promotion.

Detection is deliberately not marker-based. Reading neograph/modifier would mean importing _agent_spec_markers and creating the cycle the classifier's docstring forbids. That invariant turned out to be unguarded, so the session added a guard for it.

Half B — the data plane not landed

The gated Flow's two exit EndNodes still declare nothing, and the Flow still carries zero data_flow_connections. Its acceptance criterion names execution under the real AgentSpecLoader, and that evidence cannot be produced today. Three independent blockers, each measured against the installed SDK rather than assumed:

#ShapeBlocker
1Ungated mesh → Swarm(handoff=NEVER)ValueError: Handoff mode NEVER is not supported for conversion in LangGraph adapter. neograph exports NEVER deliberately — it is the faithful encoding of a Portal mesh's non-conversation-sharing semantics — so this is a real semantic collision, not a typo.
2Gated mesh → Flow wrapping the SwarmLoads, then dies at run time: TypeError: AgentNodeExecutor can only be used with AgentSpecAgent agents. pyagentspec accepts AgentNode(agent=Swarm) at the schema level (SerializeAsAny[AgenticComponent]) while its own reference runtime refuses to execute it. The composite is schema-legal and runtime-dead.
3Mesh membersllm_config.api_provider = None (the separate qtfof.8 gap). Even with 1 and 2 solved, execution needs a resolvable provider.
Why this half was not fixed anyway. The ticket itself says fixing an unexercised path blind is how a second silent seam gets added, and the execute skill's rule is explicit: infeasible integration blocks closure, it never downgrades the bar. The implementation atom closed; the bead did not. Landing a plausible-looking data plane against a path no runtime can execute would have satisfied the ticket's text while violating its reasoning.

Both blockers are pinned by tests that pass today and fail loudly the day either lifts — an SDK upgrade or an export-shape change. That failure is the signal that the prerequisite has been met. The prerequisite is filed as neograph-qtfof.20, now a hard dependency of qtfof.12.

10. Judgement calls, stated plainly

Four decisions in this session were judgement, not mechanics. Each is recorded here so it can be overruled rather than discovered.

  1. Widening the fix beyond its ticket. qtfof.11's ticket describes the EndNode only. The Start→body edges were added because the ticket's own fix makes them necessary — not as scope creep but as the cost of not shipping a new silent seam. The generic form also fixed the fused branch's unfiled unfed input.
  2. Repointing a conformance predicate during a bug fix. Normally out of bounds for a fix atom. Forced here: the calibration test fails if a predicate calls a cell unportable while the empirical authority executes it correctly. The alternative — a computed exemption — would have preserved a known-stale predicate.
  3. Two allowlist-style sets grew by one entry each (the designated Flow-walker set; nothing else). Both are one-per-concern registries rather than capability monopolies, and both entries carry a written justification in the guard itself. The file-size ratchet went the other way — it was lowered.
  4. The qtfof.12 reproduction contains characterization tests that assert the current broken state. That is normally an anti-pattern. It is justified only because each such assertion carries a message naming what to do when it flips, and because the alternatives — a permanently red test, or a blind fix — are worse. They must be deleted, not amended, when half B lands.

Known limits of what was proven

  • The Each collection's ordering is pyagentspec's arrival order under its APPEND reducer, not neograph's map_key order. The shared COMPARE projection is a transpose, not a rename, and the cells compared use constant bodies, so ordering was not the thing under test.
  • The collected_ guard catches the prefix as source text. A fully dynamic construction ("".join([...])) is out of reach of any static scan and is not claimed.
  • A non-EndNode downstream consumer of an Each producer remains unsupported: such a consumer must declare list[X]/dict[str, X], which _properties_for rejects outright long before any edge is emitted. That is an existing, already-loud gap, explicitly out of qtfof.11's scope.
  • The iterated_ input prefix is still hand-composed at one site. It was dispositioned ALLOWLIST, not migrated: it is shipped, execution-tested, and migrating it is a refactor of a working path, which a fix atom does not do.

11. Handoff

Nothing is stranded. The tree is clean, everything is pushed, and the molecule is closed.

  • qtfof.12 is open and blocked on qtfof.20. It should not be picked up before that; its remaining half has no way to be verified.
  • When qtfof.20 lands, the signal is mechanical: TestTheDataPlaneHalfIsBlockedByTheSdk starts failing. Then reuse close_sub_flow for the data plane — and answer, rather than override, the shape mismatch it exposes: that helper assumes one terminal producer, while a gated mesh has two exits and no terminal producer at all.
  • qtfof.19 is independent and cheap: determine empirically whether a Loop cell with a synthesized predicate now executes correctly, then either repoint the predicate or record the measured reason it must stay IR-level.
  • Worth considering: blockers 1 and 2 of qtfof.20 look like genuine pyagentspec gaps — a schema-legal composite its own adapter cannot execute, and a handoff mode the adapter refuses. Reporting them upstream may be cheaper than working around them.

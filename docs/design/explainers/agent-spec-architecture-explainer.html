Why the exported graph ran the wrong program

A shared state bus and a typed wire diagram look similar enough to confuse an exporter. Five real bugs came from that confusion. This is the mental model, the failures, the root cause, and the fix that makes the next one loud instead of quiet.

01 · The two systems don't agree on what a "graph" is

neograph compiles to LangGraph, and separately exports to Open Agent Spec (pyagentspec's Flow). Both call themselves graphs. They do not mean the same thing by it, and the exporter was written as if they did.

LangGraph's state is a shared, accumulating bus. Every node reads and writes named fields on one dict-like object. A "loop back to this node" edge is pure control — it says run this node again, nothing more. Whatever named field a node needs, it reads off the bus by name; a field simply persists until something overwrites it.

Agent Spec's Flow is a typed wire diagram. A DataFlowEdge names a source property and a destination property and asserts they're compatible — the edge is the plumbing, not a hint about it. A ControlFlowEdge is a separate, literal instruction: a real executor walks these edges to decide what runs next.

The exporter's job is to describe LangGraph's loose, name-based bus using Agent Spec's strict, wire-typed vocabulary. Every bug below is a place that translation assumed the wire model applied when the state-bus model was actually what neograph runs.

02 · Five bugs, one family

Filed independently, over several weeks, each discovered while fixing the previous one — not predicted by the architecture audit that preceded them. Read in sequence, the family resemblance is the point.

2.1 · Loop self-edge aliases a field that doesn't exist neograph‑rh5fb

A Loop-wrapped sub-construct whose input type A{v} differs from its output type B{w} compiles and runs in neograph fine — per Fig 1, LangGraph just re-enters the node; v persists, w sits in its own slot. The exporter, though, built the self-loop edge from the output field's name and pointed it at the input port:

The fix: export the self-loop as a control-only edge with no field mapping whenever the boundary types differ, mapping only fields that are structurally identical otherwise. No new mapping DSL — it mirrors what LangGraph was already doing.

2.2 · Control edges that skip the node they're supposed to run neograph‑s7zt3.15

For an Operator (human-approval gate) item, the top-level incoming edge went straight to the approval check, bypassing the body it was supposed to guard. The pause node had no outgoing edge — a literal dead end. A fused Each×Oracle's variant nodes had no inbound edge at all. None of this broke neograph's own round-trip, because its importer reads neograph/* markers and never walks the edges to execute them. A real Agent Spec runtime, walking the graph literally, would.

The fix generalizes: split each item's single "primary node" into an explicit entry plus a list of exits, and chain every exit of item N to the entry of item N+1. Every arm the item guards gets a real inbound edge; every pause reconverges on the real successor. The same do‑while vs while‑do entry bug in plain Loop export — entered at the check instead of the body — was caught by the same fix, because it's the identical mistake in a simpler shape.

2.3 · A dropped branch sentinel runs both sides of an if neograph‑s7zt3.17

The sharpest one. ForwardConstruct branches compile to a real conditional in LangGraph. The exporter walked the IR with a helper (iter_with_arms) that flattens both arms into the surrounding item list in place — convenient for other lowerings, fatal here, because the branch boundary itself disappears before the exporter ever sees it.

The lesson generalizes beyond this one bug: the reachability tests written for §2.2 pass on this broken export as-is — a flattened straight line is fully reachable. Reachability is necessary, not sufficient; see Pillar C in §04.

2.4  &  2.5 · Two schema-level collapses neograph‑p7dyq, neograph‑8zvd1

p7dyq · title inherited from the wrong owner

Two sibling fields of the same nested-model shape:

class Leaf(BaseModel): x: int
class Shared(BaseModel):
    a: Leaf
    b: Leaf

exported with titles ['Leaf','Leaf'] — the field's own name (a, b) was overwritten by the referenced definition's title. On import, two fields silently collapsed into one.

8zvd1 · a mutation the validator never saw

Dict-form fan-in titles were qualified after construction:

p.title = f"{key}.{p.title}"  # mutate post-hoc

pyagentspec only validates a title's shape at construction (no validate_assignment), so the dot slipped past the very rule that would have rejected it — then the wire read of that same property failed:

Titles of properties should not contain special
characters or blank space. Found: 'seed.entries'

The fix for both: qualify at construction, through one shared helper each caller reads — never a post-hoc field mutation that can outrun the object's own validation.

03 · The root disease

All five bugs reduce to one sentence:

the pattern

A fact about the compiled graph is re-derived locally by every consumer that needs it, instead of being read from one declared authority — and the only check that the re-derivations still agree is another consumer, re-deriving it just as leniently.

Take one concrete fact: is this modifier combination an Each×Oracle fusion? At the time these bugs were found, that single question had three independent answers living in the codebase at once:

The same shape recurs for modifier pair legality (three separate encodings inside one file, kept in sync only by a code comment admitting the hazard) and for what kind of Portal mesh member is this node (independently re-derived across seven source files, plus an eighth way in the importer).

There is a second altitude to the same disease, specific to export: the 16‑agent architecture audit that preceded these fixes claimed a "complete matrix, every cell verified, none TODO" — and was true only in the sense that every cell was verified against neograph's own importer, which never executes a control edge and so is structurally blind to exactly the defects in §2.2 and §2.3. A completeness claim checked by a lenient reader is not a completeness claim.

04 · The fix, three pillars

Pillar A · finish the classification layer

modifiers.py already owns two authorities correctly: which modifier sets are legal, and what a legal combination decomposes into. The fix extends that same table rather than adding a parallel one — a fused column, derived at definition from the existing sanctioned membership function, with a partition guard pinning that the two never drift apart again:

Pillar B · one bridge, layered

The export/import surface currently mixes a native-Spec type registry, the Agent-Spec bridge, loader dispatch, and Portal-dispatch plumbing inside modules that also do unrelated work (factory.py's Command-construction monopoly, in particular, must never be diluted). The target is a strict, acyclic layering — each module receives what it needs by injection, never by importing sideways:

Pillar C · the oracle the audit didn't have

The 2026-07 audit's blind spot was structural: its only check was neograph's own forgiving importer. The fix adds a genuine, independent oracle in three escalating tiers, over the same mechanically-generated cell matrix the audit used — so a new bug in this family fails a test the day it's introduced, not weeks later while fixing something else.

05 · Patterns worth keeping, patterns that broke this

Keep enforcing

  • Single writer per fact. One table or function owns each classification question; every consumer reads it, none re-derive it.
  • Ratchets that can only shrink. A guard's exemption list moves toward frozenset() and never grows back — the same discipline as the file-size ceiling allowlist.
  • Structural discrimination over function-local imports. When a lower-layer module needs to ask "is this a Construct?", it duck-types the shape rather than importing the higher-layer type — a function-local import to dodge a cycle just grows an allowlist that should never grow.
  • Guard-first, failing before it's fixed. Every fix above shipped its regression test red, then green, then a structural guard to keep it green.
  • Refuse a split that changes behavior. A "pure" file move that would widen a capability monopoly (Command construction, IR single-writer fields) is declined; a smaller extraction is taken instead.

What was actually broken

  • Mutating state after construction to dodge a validator (§2.5) — the qualification happened after the very check meant to catch it.
  • Verifying only against your own lenient reader (§03) — a completeness claim is only as strong as the harshest oracle that checked it.
  • An IR walk that silently drops a sentinel (§2.3) — convenient for every consumer that didn't need the branch boundary, catastrophic for the one that did.
  • Per-consumer hand-rolled dispatch (§03, Fig 3) — the same question answered a different way in six different files, agreeing by accident.
  • Single-writer discipline applied to fields but not to dispatch — the Portal rollout got IR fields right and dispatch logic wrong, in the same commit.
06 · What changes, concretely

The remaining tickets stop being independent patches and become dispositions of one design. Two are already resolved by fixes that landed upstream of this pass; the rest reshape into a twelve-phase build ordered bookkeeping → vocabulary → movers → features, with the oracle running as an early parallel track.

why this matters

The standing rule this project holds itself to: anything that compiles to LangGraph must be representable in Agent Spec, or the design is wrong. Every bug in §02 was a place that rule was silently not true. The fix is not five patches — it's making the next violation of that rule fail loud, automatically, before it ships.

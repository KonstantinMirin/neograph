---
title: Run-Scoped State
description: How a step reads a value produced earlier in the run — run identity, a session handle, a briefing — without threading it through every intervening shape.
---

A step often needs a value produced earlier in the run that is **not** what the previous step handed it. Run identity. A session handle. A briefing the model needs but no node between here and there cares about.

neograph makes steps close to pure functions on purpose: what a step consumes, it declares. That is why a graph is reviewable at all. But it would be a bad trade if the price were threading a warehouse id through six intermediate types that have no business carrying one.

`context=` is the answer, and the reference stays declared.

## The mechanism

```python
from pydantic import BaseModel

from neograph import Each, Node


class Audit(BaseModel):
    warehouse_id: int


class Discrepancy(BaseModel):
    sku: str


class Verdict(BaseModel):
    ok: bool


verify = Node(
    name="verify",
    mode="think",
    inputs=Discrepancy,     # the port: WHICH ITEM
    outputs=Verdict,
    model="fast",
    prompt="check",
    context=["audit"],      # the back-reference: WHICH RUN
) | Each(over="discrepancies.items", key="sku")
```

Every fanned branch receives its own `Claim` on the port, and the same `run_ctx` through `context`. Those are two different questions and they were never competing.

## Three properties, each load-bearing

**Declared, never ambient.** Validation checks that some upstream produces the named field, so a missing binding is a `ConstructError` at assembly — before a run, before a model sees anything. A reader of the node still sees everything it consumes. An ambient global would buy the same convenience and destroy that, which is the whole reason this is a declaration and not a lookup.

**Works under fan-out.** A fanned branch is the shape people most often assume is impossible, because the port is already spoken for by the mapped item. It is not: the two channels are independent.

**Reads state, not config.** This is the distinction to reach for when someone proposes passing the value through `run(input=...)`. Config is fixed for the run. State is not — so a session restored after a human-in-the-loop gate fires hours later is expressible here and is *not* expressible as config.

## When to use each

| You need | Reach for |
|---|---|
| A value the caller supplies and that never changes during the run | `Annotated[T, FromInput]` |
| A shared resource — a client, a limiter — configured once | `Annotated[T, FromConfig]` |
| A value **produced earlier in the run**, possibly changing | `context=[...]` |
| A value the previous step computed *for* this step | a normal typed input |

## Verbatim delivery is a property, not the purpose

Values arrive un-rendered — no BAML wrapper — which makes `context=` right for a pre-formatted catalog that must reach the model exactly as written. That is a **property of the channel**, not what it is for.

Documenting it the other way round has a cost we actually paid: the mechanism was described as "verbatim state fields injected into the prompt … for pre-formatted context like graph catalogs", and a consumer who needed precisely this capability read that, concluded it was about presentation, and filed a design proposal for a feature that already shipped. If you document a general mechanism through its narrowest use case, the people who need the general form cannot find it.

## Scripted nodes need no mechanism

`context=` resolves for LLM-mode nodes. A scripted node does not need it, and deliberately does not get one: an upstream read **is** a normal declared input, and dict-form `inputs` lets a fanned branch declare both at once.

```python
from neograph import node


class Classified(BaseModel):
    label: str


@node(outputs=Classified, map_over="discrepancies.items", map_key="sku")
def classify(item: Discrepancy, audit: Audit) -> Classified:
    """`item` is the fanned value; `audit` is an ordinary upstream read."""
    return Classified(label=f"{item.sku} [warehouse {audit.warehouse_id}]")
```

That route is **better** than `context=`, not merely equivalent: the validator type-checks a fan-in input and it creates a real dataflow edge, while a `context` field is typed `Any` and declares none. Prefer it whenever the node runs Python.

## Seeing a value is not the same as a tool receiving it

`context=` puts a value where the model can **see** it. An LLM composes its own tool-call arguments, so being shown the right warehouse does not stop it querying a different one — and that failure is quiet, because stock in the wrong warehouse reads as zero units, indistinguishable from a genuine stockout.

`Tool(bound_args=...)` closes it. The framework supplies the argument from run state, over whatever the model emitted:

```python
from neograph import Tool

Tool(
    name="check_stock",
    budget=3,
    bound_args={"warehouse_id": "audit.warehouse_id"},   # the framework's, not the model's
)
```

Arguments not named stay exactly as the model composed them. The binding is declared, so assembly fails when no upstream produces the path's root — a reference the framework resolves must be proven resolvable before a run, not silently become `None` and query the wrong thing.

Reach for it whenever the **correctness** of an argument matters rather than its plausibility. `examples/33_run_scoped_state.py` shows all three routes in one pipeline, with a fake model that queries the wrong warehouse on purpose.

## Accumulating across a fan: `Accumulate[T]`

`context=` solves *reading* a value produced earlier. Its mirror image is *writing* to one place from many — every branch of an `Each` taking readings that a judge downstream must see together. Until now a value could enter state only as a node's output, so that cost a wrapper type to carry two things through one port, a scripted node inside the branch whose only job was to push the readings out, and a hand-written merge at the parent. The failure it invited was silent: a branch returning a bare `Claim` dropped every reading it took, by construction, and the judge re-decided over the opening reads while each claim cited evidence that was gone. Green run.

An accumulator channel is declared where it is written, as a dict-form output key:

```python
from pydantic import BaseModel

from neograph import Accumulate, Each, Node


class Reading(BaseModel, frozen=True):
    claim: str
    locus: str


class Verdict(BaseModel, frozen=True):
    claim: str
    status: str


class Decision(BaseModel, frozen=True):
    loci: list[str]


verify = Node.scripted(
    "verify", fn="verify_one",
    inputs={"item": str},
    outputs={"result": Verdict, "readings": Accumulate[Reading]},   # every branch appends
) | Each(over="seed.claims", key="text")

decide = Node.scripted(
    "decide", fn="decide_all",
    inputs={"verify_result": dict[str, Verdict], "readings": list[Reading]},   # reads the union
    outputs=Decision,
)
```

The key is the channel's name. The field on the bus is `readings` — not `verify_readings` — shared by every node that declares it and merged by the same append operator the agent tool log uses. A branch body returns a list under that key (a scalar is appended as one element). A `@node` consumer is just a parameter of that name typed `list[Reading]`; the declaration is the same on all three surfaces.

Nothing else about the fan changes. `result` stays a per-branch dict keyed by the each-key, and a branch still sees only the snapshot it was sent — the channel is the one thing that unions.

**Ordering is defined, not deterministic.** The union is ordered within a branch and unordered across branches, because `Each` collects results in arrival order. Sort on a stable key you placed in the element.

**Refused at assembly**: two declarations of one channel with different element types; a channel named like a node's own field; a channel as the *first* output key of a `think`/`agent`/`act` node (the model authors that key, nothing authors a channel); a channel on an Oracle- or Portal-modified node. A node cannot read the channel it appends to.

**No representation, said aloud**: `to_agent_spec` fails loud for a pipeline with a channel — Agent Spec has no field that many nodes write — and `dump_spec` records it as a loss rather than flattening it to an ordinary `list[T]` key.

Two things the channel does not yet do: derive an agent node's append from its tool log automatically (today that is a one-line scripted node inside the branch), and de-duplicate by key. Both are tracked.

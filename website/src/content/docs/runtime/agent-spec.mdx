---
title: "Agent Spec Interop"
description: "Export a neograph pipeline to the Oracle Open Agent Spec format, and import a foreign Agent Spec back in."
---

neograph pipelines can export to and import from [Oracle's Open Agent Spec](https://github.com/oracle/agent-spec) — a flat, primitive-level interchange format — via `to_agent_spec()` and `from_agent_spec()`. This is an INTEROP layer added *beside* neograph's own high-level Spec (`_spec_schema.py`), not a replacement for it: the neograph Spec is modifier-aware (one-line `Oracle`/`Each`/`Loop` slots), while Agent Spec is flat primitives with no modifier concept.

## Why this exists

Agent Spec is a machine format other tools can read. Exporting to it means a neograph pipeline can hand off to (or interop with) any Agent-Spec-aware runtime, without neograph becoming the only place that can execute it. Importing from it means a foreign, hand-authored Agent Spec Flow can be run through neograph's compiler.

{/* test-skip: illustrative snippet, my_pipeline is a placeholder */}
```python
from neograph import Construct, to_agent_spec
from neograph.loader import from_agent_spec

flow = to_agent_spec(my_pipeline)          # neograph Construct -> pyagentspec Flow
reconstructed = from_agent_spec(flow)       # pyagentspec Flow -> neograph Construct
```

## The fidelity table: modifiers lower to primitives

Agent Spec has no concept of neograph's modifiers. Exporting *flattens* them to the primitives that already exist in the format — the same lowering neograph does when compiling to LangGraph, just expressed in Agent Spec's vocabulary:

| neograph | Agent Spec lowering |
|---|---|
| `Each` | a `MapNode` wrapping an extracted sub-`Flow` |
| `Oracle` | **no native node at all** — N parallel `LlmNode`s (fan-out) + one merge node + explicit fan-out/fan-in edges |
| `Loop` | a `BranchingNode` + a cyclic `ControlFlowEdge` back-edge + self-referencing `DataFlowEdge`s |
| `Operator` | a `BranchingNode` pause/continue split + an `InputMessageNode` |

Oracle is the flagship gap to point at: there is no first-class "ensemble" concept in Agent Spec, so a single `Oracle(n=3, merge_fn=...)` line expands into a genuinely larger flat graph — a concrete demonstration of what the modifier layer buys you.

### Combined modifiers

Modifiers **compose**, and so does their lowering. A node carrying more than one modifier is not a special case in the exporter — `Operator` is an orthogonal wrapper chained after whatever primary shape the node has, and `Each` × `Oracle` fuses into a single `MapNode` whose sub-`Flow` *is* the Oracle fan-out:

| neograph | Agent Spec lowering |
|---|---|
| `Each` + `Operator` | the `MapNode`, then the pause/continue `BranchingNode` + `InputMessageNode` |
| `Oracle` + `Operator` | the fan-out + merge group, then the pause composite chained off the merge node |
| `Loop` + `Operator` | the body + loop `BranchingNode`, then the pause composite |
| `Each` × `Oracle` | **one** `MapNode` whose sub-`Flow` holds the N variants + merge — the ensemble runs per fanned-out item |
| `Each` × `Oracle` + `Operator` | the fused `MapNode` above, then the pause composite |

All five round-trip: `to_agent_spec()` → `from_agent_spec()` recovers the original modifier combination, not a flattened approximation. Import recognizes the composed shapes structurally (a real control-flow edge into the gate, a real `pause` branch out of it) rather than trusting the metadata markers alone.

The one combination with no export is a **dispatch-mode `Portal`** (`route="decide"`), which fails loud. That is permanent, not a gap: dispatch mode synthesizes a flow from data that does not exist until runtime, and every subflow-bearing Agent Spec node takes a *static* subflow declared at authoring time. A peer-mode `Portal` mesh exports fine — as a `Swarm`.

## See it side-by-side

[`examples/31_agent_spec_each_oracle_loop.py`](https://github.com/KonstantinMirin/neograph/blob/main/examples/31_agent_spec_each_oracle_loop.py) builds three small, independent pipelines — one per modifier (`Each`, `Oracle`, `Loop`) — and for each one prints the *real* Agent Spec `Flow` that `to_agent_spec()` emits, along with its actual line count (computed from the live JSON dump, never a hand-typed number). Run it with:

```bash
uv run --extra agent-spec python examples/31_agent_spec_each_oracle_loop.py
```

Each panel then round-trips through `to_agent_spec` → `from_agent_spec` → `compile` → `run` and produces the same result as the original, non-round-tripped pipeline — proving the export isn't just structurally plausible, it's behaviorally faithful.

## Known gap: scripted-mode Oracle

Oracle currently round-trips correctly only when the generator node uses `mode="think"`. A `mode="scripted"` Oracle node reconstructs as a `think`-mode node on import regardless of its original mode — tracked as a follow-up, not yet fixed. The example above uses `mode="think"` with a keyless fake LLM, matching the currently-correct path.

## Known gap: `@node` hyphenation after round-trip

`@node` hyphenates the decorated function's name for the node label (a Python function named `each_seed` becomes `node.name == 'each-seed'`). For a scripted `@node`, that name is also the lookup key `compile()` uses to find the function — resolved per-compile from a sidecar attached to the *original* `Node` object.

That sidecar is **not** part of Agent Spec's data model, so it does not survive `to_agent_spec() → from_agent_spec()`: the reconstructed `Node` carries only the string `scripted_fn` (the exported node's hyphenated name), with no callable attached. This is intentional — `from_agent_spec()` does primitive-level import, not sidecar/modifier recovery — but it means **any scripted `@node` function, once round-tripped, needs an explicit `scripted=` kwarg at `compile()` time, keyed by the hyphenated name**:

{/* test-skip: illustrative snippet, imported/each_seed_replacement_fn are placeholders */}
```python
# each_seed() was hyphenated to 'each-seed' at decoration time.
# The natural-but-wrong guess is the underscore form matching your
# Python function name -- it also fails loud, with the same hint.
graph = compile(imported, scripted={"each-seed": each_seed_replacement_fn})
```

Passing the wrong key (or no `scripted=` at all) fails loud at `compile()` — never silently — with a hint naming the exact hyphenated key to use. If you want a scripted node to survive round-trips without repeating this `scripted=` kwarg at every call site, use the declarative `Node.scripted(name=..., fn=...)` form together with a matching module-level `register_scripted(name, fn)` call instead of `@node`'s sugar — that registration is name-keyed and global, so it survives the round-trip automatically.

## Foreign RemoteAgent import round-trips

Importing a foreign Agent Spec `Flow` whose `AgentNode` wraps a client-initiated `RemoteAgent` (`A2AAgent` or `OciAgent` — Agent Spec's "the agent runs elsewhere, this is a connection config" primitive, not something neograph exported) is a best-effort import: neograph has no runtime concept of a remote agent, so it lands as a name-bound scripted `Node` and warns. Re-exporting that reconstructed pipeline now preserves the endpoint config instead of silently downgrading it to a plain scripted node — the re-exported `AgentNode` wraps the same `A2AAgent`/`OciAgent` family, with its captured fields (including `name`) intact. If the installed pyagentspec SDK's class shape has drifted since import (a stored field no longer exists on the class), export fails loud with `ConfigurationError` rather than silently dropping the stale field.

One caveat: only the fields captured at import time round-trip — `A2AAgent.session_parameters` and `OciAgent.retry_policy` are optional fields not currently captured, so a customized value for either reverts to the pyagentspec default on re-export (a pre-existing, smaller gap than the endpoint-loss this fixed).

## Round-trip markers

Export stamps `neograph/`-prefixed metadata markers (e.g. `neograph/oracle_spec`, `neograph/each_spec`, `neograph/loop_spec`) on the lowered primitives, so a neograph-produced Agent Spec re-imports losslessly — recovering the original modifier, not just its flattened primitives. A foreign Agent Spec with no such markers still imports correctly; it just falls back to primitive-level reconstruction (no modifier recovery), since the markers are purely additive.

This is also how [Portal](/concepts/portal/)'s mode (b) dynamic dispatch works under the hood — a dispatching node emits a neograph-flavored Agent Spec at runtime and validates it before executing.
